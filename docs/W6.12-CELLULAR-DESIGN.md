## 2. daemon `cellular` 节设计（契约 §3.9 加法，WP-4）

### 2.1 节字段（`status.snapshot.cellular`）

```jsonc
"cellular": {
  "available": true,          // false = 未装 qmodem / 无模组 / 全部 section 读取失败
  "updated": 1760000000,      // 本节采样时刻
  "capabilities": { "at": true, "sms": true, "sim_switch": false, "stats": true, "temp": false },
  "modems": [
    {
      "id": "modem1",                        // uci section（qmodem.<id> 为 modem-device）
      "model": "RM500U-CN",
      "vendor": "quectel",
      "firmware": "RM500UCNCAR03A09M4G",
      "temp_c": 42.5,                        // 无则省略

      "sim": { "status": "ready", "slot": "1", "switchable": false,
               "storage": { "mem": "SM", "used": 34, "total": 60 },
               "sms_unread": 2 },
      "settings": { "mode": "auto", "prefer": "5g", "lockband": ["B3","n78"] },
      "capabilities": { "at": true, "sms": true, "sim_switch": false, "stats": true, "current_band": true, "reboot": "soft+hard" }
    }

```

**设计要点**：

1. **`available` 语义**（与 bandix 同款条件卡）：`ubus` 无 `qmodem` 对象 / `uci` 无 `modem-device` section / `modems` 为空 → `available:false`（三端一起隐藏卡片，不显示 0 值误导）。
2. **`series` 由 daemon 累积**（不依赖上游）：每慢刷压入 `signal.rsrp`，环形 60 点 → **RSRP 曲线三端同源**（Dashboard 卡 / App 概览卡 / App 蜂窝页），App 零本地累积逻辑。窗口 = 60 × 10s = 10 分钟，与预览一致。
3. **字段全部可缺省**：任一子块读取失败 → 该子块省略 + `errors[]` 记 `cellular: <method> failed`（不阻塞整节；`available` 仍 true 当且仅当至少一个模组可读）。
4. **不落盘**：节内容只存在于内存快照；短信/IMEI/ICCID 等**敏感值不进快照**（在 §3 的页面级读里按需取）。

### 2.2 采集策略（慢车道）

| 项 | 设计 |
| :--- | :--- |
| 节奏 | **10s**（第二慢车道，与 bandix 并列；与上游 `try_cache 10` 同拍 → 命中缓存，不放大 AT 压力） |
| 每轮调用 | `base_info` ×N、`sim_info` ×N、`network_info` ×N、`get_current_band` ×N、`dial_status` ×N、`get_stats` ×N（N = 模组数，**串行**，单方法 1s 超时、整节 6s 预算）；`get_connect_status`/`get_sim_slot` 仅在能力可用时调 |
| 触发条件 | 仅当 `qmodem` ubus 对象存在时启动慢刷（对象不在 → 直接 `available:false`，零调用） |
| 失败退避 | 单轮失败 → 下一轮跳过该模组一次（避免坏模组拖慢整节）；连续 3 轮失败 → `errors` 升格为「模组不可用」提示 |
| 方法分组（实现期修正，2026-10-18） | **必需 7 个**（base/network/cell/current_band/dial_status/stats/sim_info，失败记错误）× **尽力 7 个**（reset/caps/slot/mode/prefer/lockband/reboot_caps，失败静默省略）——初版把尽力方法失败也记错误，会在健康模组上刷 7 条噪音（与"坏模组刷 14 条"同类） |
| 上游形态容错（实现期修正） | 布尔字段一律走「字符串/数字/真布尔」三形态解析（`dial_status` 用 `"true"`、`supportSwitch` 用 `"0"`、jshn 输出真布尔）——防上游改形导致整块静默丢失 |
| 厂商覆盖（单测） | fixture 覆盖 Quectel（全量）/ Fibocom（**只有 RSSI+RSRQ**，无 RSRP → 曲线与质量条省略）/ Foxconn（四条齐全 + 速率用 `Mbps` 比特单位）/ generic 桩；meig 多出的 `RSCP` 条目按未知忽略。**消费方注意：无 RSRP 的厂商不显示 RSRP 曲线与质量百分比**（App 侧按 `signal.series`/`quality_pct` 缺失隐藏） |
| 开销预算 | ≤ 6N 次 ubus/10s；**实测项**（真机：CPU% 与 AT 通道争用；VM 空态验证零调用） |

### 2.3 实现位置

`internal/collect/cellular.go`（新增）+ `internal/snapshot`（结构体与序列化）+ `internal/collect/collect.go`（注册第二慢车道）+ 契约文档 §3.9 + 单测 6–8 例（解析：字符串布尔 / `available:0` 桩返回 / 缺 `modem_info` / 多模组 / series 环形 / `available:false` 三条件 / 错误隔离）。

## 3. WP-5 转发条目清单（app-api）

### 3.0 为什么不建 bridge 包（模式 A 判据，2026-10-18 补记）

TDD §5 判据：**模式 A（原生 API 驱动）= 插件自带结构化接口，直接调用；模式 B（Bridge）= 纯 LuCI 单体才写适配层**。qmodem 属模式 A——它自带 `/usr/libexec/rpcd/qmodem`（44 方法方法表 + 每方法参数声明 + 10s `try_cache` + 自带 acl.d），`luci-app-qmodem-next` 只是跑在其上的纯前端。**故本轮不新增 `quartz-cellular-bridge`**，读写各有落点：

| bridge 的职责 | 本轮落点 |
| :--- | :--- |
| 稳定读契约（隔离上游字段变化） | daemon `cellular` 采集器（映射唯一收口，三端不受影响） |
| 稳定写契约 + 参数校验 + 审计 | app-api `ubusfwd` 条目表（§3.1，机制现成） |
| ACL / 暴露面 | 不涉及：daemon 与 app-api 均为 root 侧调用（不经 session） |
| 集成默认值（如 bandix bridge 的 uci-defaults 默认开启） | **缺口，另落**：qmodem 流量统计 NVM 持久化默认关（`usage_stats_nvram_save`）、重置计划定时任务 —— 归**设备/配置层**（`devices/<机型>/` uci-defaults 或 preinstall 层，与 fancontrol 曲线同款），不开 bridge 包 |

**代价**：上游方法改名需改两处（采集器 + 条目表）而非一处；缓解 = 受控 fork 锁 tag（`v3.4.0_rc3-quartz1`）+ 探针加版本串（§5.3）。
**何时回头建 bridge**（任一成立再评估）：① 需跨机型写面语义归一（各家"锁频段"AT 方言不同、要统一成一套参数）；② 需一次调用组合多步业务；③ 需向非 root 的 LuCI 会话开放这些能力（ACL 场景）。

## 5. App 蜂窝 tab（WP-6：W6.12–W6.14）

### 5.1 门控与骨架

## 6. 验收清单

**VM（x86_64，无模组）**——可验：
1. 契约：`cellular` 节存在性、`available:false` 三条件（未装/无 section/读取全失败）、字段缺省不崩、`v` 不变。
2. 转发：全部条目注册与参数校验负例（非法 `at`/`imei`/`slot`/`index`）；错误映射（`data_unavailable` → "qmodem unavailable"）。
3. 会话/审计：AT 与写动作各留一行 logd；`send_at` 在无模组时的失败语义（`action_failed` + detail）。
4. 空态 UI：蜂窝 tab 不显示（`available:false`）；粘性标记行为（配对 A 有模组 / 重配对到 B 无模组 → 消失）。
5. 开销：无 qmodem 时零调用；有对象无模组时的调用次数与耗时。

**真机（FNet3399 + 5G 模组）**——必须：
6. 真数据：模组型号/固件/信号四值/服务小区（PCC+NSA 的 ARFCN·PCI·带宽）/拨号状态与速率/本月流量/SIM 与短信存储。
7. 拨号控制：断开 → 状态翻转 → 重拨 → 恢复；`modem_hang` 危险确认文案生效。
8. 短信：列表拉取、发送（真机送达）、删除、存储切换；转发规则深链可跳。
9. AT：预置命令与网页端**逐条一致**（同模组对比）；发送真实命令（如 `AT+QCAINFO`）响应一致；`lang` 参数生效（中文 App 得中文命令名）。
10. 能力协商：`get_stats`（非 Quectel → `available:false` 说明）、`sim_switch`（`supportSwitch=0` → 只读）、`reboot_caps` 软硬区分。
11. 开销与争用：10s 慢刷下的 CPU%；与网页端 AT 调试并发时的表现（缓存命中）。
12. 断网恢复：拔卡/断信号 → 节降级 → 恢复后自愈。

## 7. 风险与坑位预判（进实现时逐条验证）

| # | 风险 | 应对 |
| :--- | :--- | :--- |
| 1 | `dial_status` 返回**字符串** `"true"`——Go 侧 `json.Unmarshal` 进 bool 会报错 | 解析用 string，再判等；单测覆盖 |
| 2 | generic 桩返回（`get_stats.available=0`、`supportSwitch=0`）易被误读为「0 流量/不可切换」 | 一律按 `available`/`supportSwitch` 门控 UI，不展示 0 值 |
| 3 | AT 通道争用（daemon 慢刷 + 网页端 + App 同时发命令） | 上游 10s 缓存 + daemon 串行 + App 侧命令发送串行化；真机验收项 11 |
| 4 | `get_sms` 在大容量 SIM 上可能慢 | 上游 10s 缓存；App 页面按需刷新（不做 5s 轮询）；超时给明确提示 |
| 5 | 敏感数据（IMEI/ICCID/短信） | **不进快照**；仅页面级读；App 内存态不落盘；审计只记命令与结果码，不记内容 |
| 6 | `set_lockband`/`set_mode` 参数语法随厂商不同 | app-api 只做字符集与长度校验，语义交由上游；失败回 `action_failed` + detail |
| 7 | `modem_hang`/`set_sim_slot` 会**当场断网**（若 LAN 走模组） | 危险动作：底部确认层 + 「可能断开本机连接」文案（沿用既有危险动作模式） |
| 8 | 多模组 section 名注入 | section 必须 ∈ 已知 `modem-device` 白名单（daemon 与 app-api 两侧各自校验） |
