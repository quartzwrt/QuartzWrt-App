# QuartzWrt App · UI 设计（定案 v0.3）

**状态**: **定案 v1.0**（2026-10-13：七项拍板见 §6；应用 tab 细化与「操作记录」经用户确认并入，见 §5）。
**预览**: `design/preview.html`（十二屏，评审图 `design/shots/`）。
**依据**: `docs/DESIGN.md` §8（信息架构）；WP-2 视觉 token（macOS Vibrancy）；AGGREGATE-API v1 数据面；WP-5 接口面（认证/动作）；WP-3 §6 / WP-4 §13 扩展思想在 App 端的落地。

## 1. 设计语言（与 WP-2 同源）

- **token**：强调 `#007AFF` / 正常 `#34C759` / 注意 `#FF9500` / 危险 `#FF3B30`；深色底 `#1C1C1E`·面板 `#2C2C2E`·浮起 `#3A3A3C`；浅色底 `#ECECF0`·面板 `#FFF`。圆角卡片 12 / 控件 8。
- **材质**：统一 1px 描边分层（深色为白 9% / 浅色为黑 8%），无渐变、无发光，仅颜色过渡；数字一律 tabular-nums（速率/百分比不抖动）。
- **字体**：系统字体栈（零 webfont）。中文优先（zh 文案随 arb 走）。
- **状态语义**：`●` 绿=运行/在线 · 橙=注意 · 红=危险/离线 · 灰=未安装/停用。
- **图标**：线稿图标（1.8–2px 线宽）；应用图标复用 WP-2 切面宝石 logo（安卓自适应图标全套 W6.6 出图）。

## 3. 交互与控制落点（定案）

- **导航**：底部四 tab；配对前无 tab 的单任务流；详情页 push（back 返回），不占 tab。
- **控制按域归口（拍板 3）**：**对设备本身的控制 → 设置·系统设置**（重启路由器/重启服务）；**对网络的控制 → 网络页**（网络服务行；WAN 重连等经 WP-5 动作表扩展位）；**单应用控制 → 应用详情页**（⑪）。
- **数据刷新**：前台 5s 轮询（契约 §5）；下拉刷新；后台停取、回前台补取。
- **控制反馈**：动作中行内 loading；成功 ≤2s 快照自动反映；失败按 `action_failed.detail` 展示。
- **危险动作**：底部确认层（拍板 4）；连断动作（停网络/SSH 类）v1 不进 UI。
- **空态/降级**：不白屏（⑨）；指纹变化（重刷固件）→ 阻断 + 引导重配对。
- **远程链路（W6.5）**：hero/设置配对卡徽标 = 「局域网｜远程」（远程带云标与强调色）；端点传输级失败自动切换（局域网优先）、回前台探测切回；远程地址增删改在 ⑬ 页（严格 pin 实测连通才保存）。

## 4. 可扩展性设计（扩展模型，定案 7）

**目标**：路由器侧持续长新东西（daemon 新节、新插件、WP-8 Bridge 新动作、WP-9 OTA），App **不因新功能重做布局**；成本阶梯：`0 行` → `1 条注册表项` → `1 个页面模块`。

### 4.1 四层扩展阶梯

| 层 | 路由器侧供给 | App 成本 | 体现 |
| :-- | :--- | :--- | :--- |
| **L0 数据容忍** | 契约加法 / 未知键 | **0 行**（模型层已就位） | 新字段/新服务到达不崩 |
| **L1 泛化渲染兜底** | 新 daemon 节 / 新服务键（WP-4 探针描述文件，零重编） | **0 行** | 未知节 → 通用 KV 卡（≤6 行，超限进详情）；未知服务 → 泛化行（title + 状态点） |
| **L2 注册表增强** | 同上（要更好的呈现时） | **1 条注册表项** | bespoke 卡（sparkline 网络卡/无线卡）；服务富化行；动作条目 |
| **L3 新页面模块** | 新功能域（配置流/详情，WP-8/WP-9） | **1 个 feature 模块 + 1 条路由** | 应用详情（⑪）、DDNS 配置页、固件升级页 |

### 4.2 代码机制（W6.3 实施规范）

- **卡片注册表**：`lib/features/overview/cards/` 一卡一文件，`CardSpec{id, order, visible(Snapshot), build(ctx, Snapshot)}`；`registry.dart` 汇总。可见性谓词统一处理节缺失/为 null（**Docker 卡即此机制：`docker.available==true` 才渲染**）。
- **通用兜底卡**：未被任何 CardSpec 消费的顶层节自动追加通用 KV 卡（⑩ 的 USB 存储即此）。
- **服务/应用行 spec**：`ServiceRowSpec{id, title(ctx,data), enrich(data)}` + 默认泛化行（title 取数据 `title` → i18n 映射 → id 原样；running 状态点）。
- **动作能力注册表**：`ActionSpec{id, label, danger?, confirmText?, params?, enabled(snapshot), run(client)}`；系统设置动作区/网络服务行/应用详情页**只渲染注册表**。WP-5 白名单或 WP-8 Bridge 新增动作 = 加一条注册 + arb 文案。
- **路由**：go_router 声明式；路径 `/<tab>/<feature>/<id>`？详情页 `/<tab>/detail/<id>`；新页面 = 加路由条目。
- **注册单点**：`lib/features/registry.dart`（cards/services/actions 三张表），评审一次 diff 看到"新功能做了什么"。

### 4.3 信息架构留位（拍板 1 落地）

- **tab 位预置 5 个：4 显示（概览/网络/应用/设置）+ 1 隐藏预留**（给后续功能，如未来的流量分析域）。
- **新功能默认不新开 tab**，落三类位：概览**卡** / 既有 tab 的**行** / **详情页**；启用第 5 个 tab 需满足「多页面 + 独立上下文 + 高频入口」且过设计评审。
- 概览卡片注册表追加即增长；排序/显隐（「编辑」）后置（拍板 5）。
- 第三方插件无专属 UI 的兜底：⑩⑪ 模式（泛化行 → 详情 → 动作注册表）；App 不解析插件私有数据、不嵌 LuCI 页（TDD §5）。

### 4.4 边界（明确不做）

运行时 UI 下发；webview 化插件页；为单插件开私路（缺入口 = 路由器侧应补 API）。

### 4.5 端到端走查

1. **daemon 新节**（如 wireless/USB 存储）：契约加法 → App 零改动出通用卡（⑩）→ 需要时补 1 个 CardSpec 富化（④ 无线卡即目标形态）。
2. **新插件（模式 B）**：WP-8 `quartz-ddns-bridge` → 探针描述文件 → `services.ddns` 出现 → 应用列表泛化行自动出现；WP-5 动作表加 `ddns.update` → 注册表加一条 → 应用详情出现「立即更新」。
3. **top-level 新功能**：WP-9 OTA → 系统设置加一行「固件更新 ›」 + 1 个升级页——tab 结构不变（需要时再启用预留第 5 tab）。

## 5. 应用 tab（含软件包管理）——已确认并入定案

**定位**：应用 tab = **「应用」（控制面）+「软件包」（管理面）**两个子段；应用详情（⑪）为两面汇合点。

| 面 | 内容 | 数据/动作来源 | 现状 |
| :-- | :--- | :--- | :--- |
| 控制面（子段「应用」） | 已安装且可控制的应用；启动/停止/重启；应用详情（状态 + 动作） | 快照 `services` 开放映射（**已有**）；WP-5 动作 `service.{start,stop,restart}`（**已有**） | 可直接实现 |
| 管理面（子段「软件包」） | 可升级列表（版本 diff）/已安装（版本·大小）/全部（搜索）；升级（单/全部）/刷新索引/卸载 | **需 WP-5 扩展（加法）**：①读方法 `packages`（列表·版本·可升级，**分页**返回——避免塞进 32KB 快照）；②动作 id `packages.refresh` / `packages.upgrade` / `packages.remove`（通用 `action` 方法加白名单条目即可；卸载/安装=危险动作+底部确认层）；数据源=路由器 apk 体系（与 LuCI 软件包页同源） | 需 WP-5 追加（登记项，见下） |
| 安装新包（浏览软件源） | 「安装新软件包」入口 | 需再扩展读方法（可用源/搜索）+ `packages.install` | **v1 后置**（已确认；先做「已安装/升级/记录」闭环） |
| 操作记录（**已确认**） | 升级/卸载/刷新执行结果（含失败原因，保留近 30 条）；软件包子段右上「记录」入口 → 独立页（⑫） | WP-5 结构化保存近况（审计流的小读面；`packages` 读方法 `scope=history`） | 随 packages 扩展一起做 |

**跨 WP 登记（已确认，2026-10-13）**：WP-5 方法表扩展——读方法 `packages`（`scope=installed|upgradable|available|history`，分页）+ 动作 `packages.refresh/upgrade/remove` 白名单条目（卸载=危险动作+确认层；`history` 供 ⑫ 操作记录）；WP-6 侧对应 L2 注册表（动作条目）+ L3 页面模块（软件包页/操作记录页），**不改既有结构**（扩展模型 §4 的实例）。
