## 4. 后端能力契约（前端直接照抄）

**方法**：都是 `quartz-app-api` 顶层方法（与 `status`/`action` 同级），走 `/ubus` JSON-RPC 扁平参数形态。

```
params: [ "<sid 任意>", "quartz-app-api", "config.read", {…} ]
```
（VM 实测：rpcd `/ubus` 要**扁平**形态 `[sid, object, method, args]`；嵌套 `[sid,"call",{…}]` 会得 `-32700`。）

| 方法 | 参数 | 返回（`result[1]` 载荷） |
| :--- | :--- | :--- |
| `config.read` | `access_token, config, section?, option?` | `{ok, config, section, option, value}`；**全量读** `value` = `{节名: {选项: 值}}`；**读 section** 同形单节；**读单 option** `value` = 标量（未设置 = `null`；敏感项 = `"__masked__"`） |
| `config.write` | `access_token, config, section, option, value` | `{ok, changes:{changes:[[op, section, option, value], …]}}`（**暂存，未落盘**） |
| `config.changes` | `access_token, config` | 同上形态（待应用改动） |
| `config.revert` | `access_token, config` | `{ok, reverted}`（**只丢弃暂存**；apply 后不能用它撤销已生效配置） |
| `config.apply` | `access_token, rollback?:bool(默认 true), timeout?:int(默认 90)` | `{ok, applied, rollback, timeout}` |
| `config.confirm` | `access_token` | `{ok, confirmed}` |
| `config.rollback` | `access_token` | `{ok, rolled_back}`（**立即回滚已 apply 未 confirm 的改动**，r9 新增） |

**错误码**：`forbidden_action`（未注册配置/节/选项）、`bad_request`（类型/枚举/范围/字符集/掩码回写）、`data_unavailable`（**配置会话不可用**，文案含"请重新登录路由器以启用配置功能"）、`action_failed`（uci 执行失败，detail 带上游串）。

**已注册字段（试点，按节完整）**：见 `Packages/utils/quartz-app-api/src/internal/uciconf/registry.go`——`network.lan/wan`（proto/ipaddr/netmask/gateway/dns/ip6addr/ip6assign/device/disabled/auto/username/password）、`wireless @wifi-device|@wifi-iface`（disabled/channel/htmode/txpower/country/band/cell_density/distance；ssid/encryption/key/hidden/isolate/wmm/network/mode）、`dhcp @dnsmasq|@dhcp`、`system @system`。字段级类型/枚举/字符集即"契约真相"，**前端不要自己另立限制**。

## 5. 机制与坑（务必先读，全部 VM 实测）

1. **每个方法要两处登记**，漏一个就 100% 失败：
   - `cmd/quartz-app-api/main.go` 的 `methodList()`（rpcd 方法签名）——漏 → 方法不存在/参数拒绝；
   - `files/acl.d/quartz-app-api.json` 的 `unauthenticated.read.ubus["quartz-app-api"]`——漏 → `-32002 Access denied`。
2. **app-api 是 rpcd exec 插件，每次调用都是新进程** → 任何跨调用状态必须落盘（`/etc/quartz-app-api/state.json`，0600）。
3. **uci 写入/apply/confirm 必须同一条 `ubus_rpc_session`**；`session create` 拿到的会话是**空 ACL**（写 uci 被拒），只有 `session login`（管理员凭据）可用。实现：**login 时开启保留会话（12h）并把 sid 存进设备记录**，logout/revoke 时 `session destroy`。sid 失效 → `data_unavailable` + 重新登录提示。
4. **`uci apply` 的 rollback 计时器与 apply_sid 是 rpcd 全局单例** → 同一时刻只能有一处挂起 apply；App 侧配置应用要**串行化**，与网页端同时操作时后者会 `PERMISSION_DENIED`（提示"网页端有未确认的更改"）。
5. **`uci get` 带 `option` 时返回 `{"value":["<值>"]}`（数组包装，未设置为空数组）**；不带 option 才是 `{"values":{…}}`。无参 uci 方法必须传 `{}`（传 `null` 会被 rpcd 判解析失败）。
6. **敏感字段**：`wireless.@wifi-iface[].key` 与 `network.wan.password` 读面自动掩码为 `"__masked__"`，回写该占位符会被 `bad_request` 拒绝——App 必须"未修改则不发该字段"。
7. **apply 后必须给确认 UI**（90s 倒计时 + "保留更改/立即回滚"），否则 90s 后自动回滚；这是改 LAN IP/无线密码时的唯一自救路径。**立即回滚调 `config.rollback`（不是 `config.revert`）**——VM 实测 apply 后 `uci revert` 不撤销已生效配置，还会解除回滚计时器。
8. **扩展注册表**（W6.11+）：在 `registry.go` 加 `configSpec`/`sectionSpec`/`optionSpec`（类型/枚举/范围/字符集/`Sensitive`），补单测；**不要**为单个键开白名单散点。

```bash
# 1) 单元测试
cd QuartzWrt-Packages/utils/quartz-app-api/src && ~/go-sdk/bin/go test ./...   # 12 包
cd QuartzWrt-Packages/utils/quartz-daemon/src   && ~/go-sdk/bin/go test ./...   # 5 包
cd QuartzWrt-App && flutter analyze && flutter test                             # 89 项

# 2) 包级编译（构建树对 quartz feed 是 src-link，改动直接生效）
cd QuartzWrt-Builder/../build/immortalwrt
make package/quartz-app-api/{clean,compile}     # 产物 bin/packages/x86_64/quartz/*.apk

# 3) 推进 VM（宿主 HTTP + guest slirp 别名；端口可自选）
(cd build/immortalwrt/bin/packages/x86_64/quartz && python3 -m http.server 8891 --bind 127.0.0.1 &)
python3 Packages/utils/quartz-daemon/dev/vm-ssh.py \
  'cd /tmp && wget -q http://192.168.1.2:8891/quartz-app-api-0.1.0-rN.apk -O q.apk && apk add --allow-untrusted q.apk && killall -HUP rpcd'

# 4) 验收（脚本自带 PASS/FAIL 汇总与日志落盘）
Packages/utils/quartz-app-api/dev/vm-accept-config.sh          # 17/17
Packages/utils/quartz-daemon/dev/vm-accept-cellular.sh         # 18/18
cd QuartzWrt-App && dart run tool/e2e_vm.dart                  # 19 项
```
